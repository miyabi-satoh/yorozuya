掃除の目的は、なるべく再生成できるもので容量を空けること。
**何を消すかはユーザーが決める。** このセッションは、候補を漏れなく探し、消すと何を失うかを具体的に示すところまでを引き受ける。

## 手順

1. **空き容量を記録する。** macOS / Linux は `df -h ~`、Windows は `Get-PSDrive`。最後に差を出すのに使う。

2. **候補を探す。この段階は読み取りだけ。** 2方向から当たる。
   - 上から: ホームと作業ディレクトリの直下を測り（`du -sh -x <dir>/* 2>/dev/null | sort -rh | head -20`）、大きいものの中へ降りていく。
   - 目録から: [references/catalog.md](references/catalog.md) の定番の場所のうち、この環境にあるものを測る。コマンドが入っているか、ディレクトリがあるかで判断する。

   目録に無いものも候補にしてよい。
   完了条件は、測った上位の場所が「候補」「触らない」「不明」のどれかに**すべて**振り分けられていること。
   大きな木の `du` は時間がかかるので、バックグラウンドで回してよい。

3. **候補ごとに3つを確かめる。**
   - **消し方**: 道具自身の掃除コマンドがあればそれを使う。書式はバージョンで変わるので `--help` で確かめる。
   - **失うもの**: 次に使うとき自動で作り直されるか。作り直しに要るもの（ダウンロード・ビルド時間）。作り直せない情報（履歴・復元点・手元にしかないデータ）があるか。
   - **持ち主**: 稼働中のプロジェクトのものか。セッションが開いている、直近に更新がある、で判断する。

   プロジェクト内の成果物は `git check-ignore -q <path>` で無視対象か確かめる。無視されていないものは成果物ではなく、ソースやデータの可能性がある。

4. **レポートして、何を消すか聞く。** 区分ごとの表にし、各表はサイズの大きい順に並べる。合計の見込みも出す。

   | 区分 | 意味 |
   | --- | --- |
   | 再生成できる | 消しても、次に使うとき作り直されるだけ |
   | 失うものがある | 失うものを具体的に書く（「resume できなくなる」「再ダウンロードに数GB」など） |
   | 持ち主に頼む | 稼働中のプロジェクトのもの。消し方の依頼として示す |
   | 触らない / 不明 | 理由を一言添える |

   表の各行には、パス・サイズ・消し方（コマンド）・失うもの を載せる。

5. **選ばれたものだけ消す。**
   - 「再生成できる」は区分ごとの承認でよい。「失うものがある」は項目ごとに選ばれたものだけ消す。
   - 対象はレポートに載せたパスとコマンドに限る。消す直前に、そのパスがレポートしたものと同じであることを確かめる。
   - 1件失敗しても残りを続け、失敗は最後にまとめる。
   - 「持ち主に頼む」は、そのプロジェクトのセッションへの委譲かユーザーへの案内にする。

6. **結果を報告する。** 空き容量の前後の差、消したもの、失敗したもの、残った依頼。

## 判断の基準

**迷ったら「失うものがある」側に置く。** 区分を下げるのはユーザーの判断で、上げるのはこのセッションの判断。

**自動で掃除される仕組みがあるなら、手で消すより設定を案内する。** 手で消しても、また溜まるのを待つだけになる。

**触らないもの。** 認証情報、設定ファイル、インストール済みのプラグインや拡張、エージェントのメモリ、ソースコードと未コミットの変更、アプリの利用データ（ブラウザのプロファイル、仮想マシンのイメージ、データベースのデータ）。
容量が大きくても「触らない」に置き、どうしても空きが要るならユーザーに事情を伝えて判断を仰ぐ。

**使用中のものは消さない。** 動いているプロセスが使っているキャッシュ（ビルド中の `target/`、起動中の Docker のイメージなど）は、止まってから。

## 詰まったとき

- **消したのに空きが増えない** — ゴミ箱、APFS のローカルスナップショット（`tmutil listlocalsnapshots /`）、削除済みでも開かれたままのファイル（`lsof +L1`）を当たる。
- **掃除コマンドが失敗する** — 書式の変化を疑い `--help` を読む。直接 `rm` に切り替えるのは、そのディレクトリが丸ごと再生成できると確かめてから。
- **同じ場所がすぐ膨らむ** — 堆積ではなく現行の使用量のことがある。消す前に中身の日付を見る（`find <dir> -mtime +30 | wc -l`）。古いものが無ければ、掃除ではなく設定（ビルドのデバッグ情報を減らす等）の話なので、持ち主に伝える。
