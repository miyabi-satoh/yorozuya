掃除の目的は、作り直せるもので容量を空けること。決まりは3つ。

1. **消してよいのは、[references/catalog.md](references/catalog.md)（目録）に載っている種類だけ。** 目録に無いものは、大きくても「参考」として見せるだけにする。
2. **消し方は目録に書いたコマンドかパスだけ。**
3. **消す直前に確かめ直す。**

調査は長くかかる。その間もユーザーが別の頼みごとをできるよう、調査はバックグラウンドのサブエージェントに任せる。

## 手順

1. **空き容量を記録する。** macOS / Linux は `df -h ~`、Windows は `Get-PSDrive C`。

2. **調査をサブエージェントに任せて、ターンを終える。**
   バックグラウンドで動くサブエージェント（Claude Code なら Agent ツール）に、[references/survey.md](references/survey.md) の手順で調べるよう頼む。依頼に書くこと:
   - survey.md と catalog.md の**絶対パス**（サブエージェントの cwd は skill のディレクトリではない）
   - 測る場所（ホーム・作業ディレクトリなど）。並列に分けるなら範囲が重ならないように
   - セッションの動いているプロジェクトのパス（`ListAgents` などで引いておく）
   - 読み取りだけで、削除・移動・書き込み・prune 系・他のセッションの操作をしないこと

   頼んだら「調べています。終わったら報告します」と伝えてターンを終える。結果は自動で届く。
   サブエージェントを使えない環境では、survey.md の手順を自分で行う。

3. **結果が届いたら、確かめ直してからレポートし、何を消すか聞く。** ユーザーが別の話の途中なら、そちらを片付けてから出す。
   「消せる」の行はすべて、目録の行とその条件に合っているか、稼働中のプロジェクトのものでないかを自分で確かめる。合わない行は「持ち主に頼む」か「参考」に移す。サブエージェントの区分は甘くなりやすい。

   | 区分 | 中身 |
   | --- | --- |
   | 消せる | 目録に載っているもの。パス・サイズ・消し方・失うものを載せる |
   | 持ち主に頼む | セッションの動いているプロジェクトのもの |
   | 参考 | 目録に無い大きいもの。見せるだけ |

4. **選ばれた行だけ消す。**
   - 消す直前に、パスがレポートしたものと同じか、使用中（起動中のアプリ、ビルド、コンテナ）でないかを確かめる。
   - 1件失敗しても残りを続け、失敗は最後にまとめる。
   - 「持ち主に頼む」は、そのプロジェクトのセッションに依頼する。

5. **結果を報告する。** 空き容量の前後の差、消したもの、失敗したもの。

## 目録に無いものを消したいと言われたら

その場で消さず、何を失うかをユーザーと確かめて、目録に行を足してから消す。目録に足した行は次の掃除でも使える。

## 詰まったとき

- **消したのに空きが増えない** — ゴミ箱を空にしたか。macOS ではローカルスナップショット（`tmutil listlocalsnapshots /`）と、開かれたままの削除済みファイル（`lsof +L1`）。仮想ディスクはファイル自体が縮まないことがある。
- **掃除コマンドが失敗する** — `--help` で書式を確かめる。目録の注意書きも読む。
- **同じ場所がすぐ膨らむ** — 堆積ではなく現行の使用量のことがある（`find <dir> -mtime +30 | wc -l` で古いものを数える）。古いものが無ければ、掃除ではなく設定の話として持ち主に伝える。
