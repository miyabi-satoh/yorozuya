掃除の目的は、なるべく再生成できるもので容量を空けること。
**何を消すかはユーザーが決める。** このセッションは、候補を漏れなく探し、消すと何を失うかを具体的に示すところまでを引き受ける。

調査は長くかかる。その間もユーザーが別の頼みごとをできるよう、**調査はバックグラウンドのサブエージェントに任せ、このセッションは手を空けておく。**

## 手順

1. **空き容量と使用量を記録する。** macOS / Linux は `df -h ~`、Windows は `Get-PSDrive C`（Used と Free）。空き容量は最後に差を出すのに、使用量は測った合計との照合に使う。

2. **調査をサブエージェントに任せて、ターンを終える。**
   バックグラウンドで動くサブエージェント（Claude Code なら Agent ツール）に、[references/survey.md](references/survey.md) を読んでその手順で調査するよう頼む。
   依頼には、調べる場所（ホーム・作業ディレクトリなど）、ディスクの使用量、稼働中と分かっているプロジェクトを添える。
   場所が多ければ、場所ごとに分けて並列に走らせてよい。
   頼んだら「調べています。終わったら報告します」とだけ伝えてターンを終える。結果は自動で届くので、待たない。
   サブエージェントを使えない環境では、survey.md の手順を自分で行う。

3. **結果が届いたら、レポートして何を消すか聞く。**
   ユーザーが別の話の途中なら、そちらを片付けてから出す。
   サブエージェントの表を区分ごとに並べ直し、合計の見込みを出す。
   削除を頼む前に、表の中で疑わしい行（区分が甘い、持ち主が曖昧）は自分で確かめ直す。

4. **選ばれたものだけ消す。**
   - 「再生成できる」は区分ごとの承認でよい。「失うものがある」は項目ごとに選ばれたものだけ消す。
   - 対象はレポートに載せたパスとコマンドに限る。消す直前に、そのパスがレポートしたものと同じであることを確かめる。
   - 1件失敗しても残りを続け、失敗は最後にまとめる。
   - 「持ち主に頼む」は、そのプロジェクトのセッションへの委譲かユーザーへの案内にする。

5. **結果を報告する。** 空き容量の前後の差、消したもの、失敗したもの、残った依頼。

## 判断の基準

**迷ったら「失うものがある」側に置く。** 区分を下げるのはユーザーの判断で、上げるのはこのセッションの判断。

**自動で掃除される仕組みがあるなら、手で消すより設定を案内する。** 手で消しても、また溜まるのを待つだけになる。

**触らないもの。** 認証情報、設定ファイル、インストール済みのプラグインや拡張、エージェントのメモリ、ソースコードと未コミットの変更、アプリの利用データ（ブラウザのプロファイル、仮想マシンのイメージ、データベースのデータ）。
容量が大きくても「触らない」に置き、どうしても空きが要るならユーザーに事情を伝えて判断を仰ぐ。

**使用中のものは消さない。** 動いているプロセスが使っているキャッシュ（ビルド中の `target/`、起動中の Docker のイメージなど）は、止まってから。

**削除はこのセッションだけが行う。** サブエージェントは測って調べるところまで。

## 詰まったとき

- **消したのに空きが増えない** — ゴミ箱を当たる（macOS `~/.Trash`、Windows `C:\$Recycle.Bin`）。macOS では APFS のローカルスナップショット（`tmutil listlocalsnapshots /`）と、削除済みでも開かれたままのファイル（`lsof +L1`）も。仮想ディスクの中身を消した場合は、ディスクのファイル自体が縮んでいないことがある。
- **掃除コマンドが失敗する** — 書式の変化を疑い `--help` を読む。直接 `rm` に切り替えるのは、そのディレクトリが丸ごと再生成できると確かめてから。
- **同じ場所がすぐ膨らむ** — 堆積ではなく現行の使用量のことがある。消す前に中身の日付を見る（`find <dir> -mtime +30 | wc -l`）。古いものが無ければ、掃除ではなく設定（ビルドのデバッグ情報を減らす等）の話なので、持ち主に伝える。
