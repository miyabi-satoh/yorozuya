# キーボードやマウスを奪う処理の鍵

同じマシンの別のセッションと操作がかち合うと、どちらも失敗する。クリックが別の窓に入る、フォーカスが移って入力が迷子になる、といった形で壊れる。負荷と違って、他のセッションが今まさに触ろうとしているかを自分で測る手段が無いので、始める前にマシンに1つの鍵（`machine-locks` の input の鍵）を置き、終わったら外す。鍵を見るのは自動操作をしようとしたセッションだけで、関係の無いセッションの会話は流れない。鍵が要るかは、操作が入力やフォーカスを使うかで決める。`osascript` のキー送出、`cliclick`、`SendKeys`、UI Automation、`xdotool` なども、その場で何をするかを見る。窓か範囲を指して撮るだけの画面の取り込み（`screencapture -x -l <窓の番号>`・`-R`）は、ポインタもキーもフォーカスも使わないので、鍵も了承も要らない。選ばせる・撮った後に開く・録画する選択肢を付けたもの、窓も範囲も指さないもの（クリックを待つことがある）は要る。窓やアプリを前に出す操作（`open` など）は、自分の判断で行うときは鍵を置く（ユーザーが手元で入力している先を奪う）。ユーザーに開くよう頼まれたときは置かない（ユーザーはその窓を待っていて、ぶつからない）。

## 仕事

入力を奪う処理の前に鍵を置き、終わったら外す。ほかのセッションの鍵があれば、外れるまで始めない。始める前にユーザーに伝え、ユーザーの了承を受けてから始める。

## やらないこと

- 鍵のことをほかのセッションへ知らせない — 鍵を見るのは自動操作をするセッションだけで足り、知らせると関係の無いセッションが1ターン返すことになる。

## 出力

鍵（`machine-locks` の input の鍵）の置き・外しと、返答の文で伝える、始めることと返したことの知らせ。

## 終わる条件

鍵を外したとき（途中でやめたときも外す）。

## 止まる条件

次のときは推測で埋めずに止まり、ユーザーに聞く。

- 必要な情報が分からないとき: ほかのセッションの鍵が、延ばされ続けて外れないとき。黙って始めない。

## 手順

1. ユーザーに、何をどのくらいの時間奪うかと、その間にしてよいこと・いけないこと（下の「環境ごとの注意」）を伝え、了承が返ってから鍵を置いて始める。画面とフォーカスを奪うので、ユーザーが手元で操作を続けていると、その入力が自動操作の先に入る。了承を待つのは、ユーザーが手を離せる時機をユーザーが決めるため。了承は、受けてから10分のあいだ、鍵を持ったまま別の操作に移ることに効き、過ぎたら取り直す（1つの作業で何度も取り直すと、了承が多すぎるため）。鍵を外した後と、鍵が見込みの時間を過ぎて切れた後は、10分のうちでも、また奪う前に了承を取り直す。どちらもユーザーは使ってよいと知らされて手元の操作に戻るので、黙って奪い直すと、いつ触ってよいかが分からなくなる。流し直しや撮り直しが続きそうなら、鍵を外さずに延ばす。断られたら、次に始めるときもまた聞く。
2. 鍵を置く。何をするかと、終わるまでの見込みの分を付ける。見込みを過ぎた鍵は無いものとみなされるので、持ち主が外さずに落ちても、ほかのセッションは見込みの時刻のあとに始められる（Claude Code のセッションが落ちたときは、見込みの時刻より前でも外れる）。
   - ほかのセッションの鍵が効いていれば、置けない。断りに出る持ち主のフォルダと残りの分を見て、見込みの時刻を過ぎるか外れてから置き直す。待つ間にできる作業は先に進める。
   - 見込みより延びそうなら、過ぎる前に置き直して延ばす。
   - 置いたら、操作を始める前に、返答の文で「いまからキーボードとマウスを使います。触らないでください」と伝える。了承のダイアログに答えたユーザーにも、いつ始まったかを会話で残すため。
3. 終わったら外す。途中でやめたときも外す。外したら、すぐ返答の文でユーザーに「キーボードとマウスを返しました。もう使って大丈夫です」と伝える。Claude Code で mod が出す知らせ（下の「Claude Code では」）があっても、返答に書く。ユーザーは、いつ手元の操作に戻ってよいかを自分では知れず、自動操作の間はそのペインを見ていないことが多い。会話の画面だけを読んでいると、mod の1行や toast は見落としやすい。
   - 外す前に、確かめのために開いた窓・アプリ・ファイル（`open` で開いた Finder の窓・試しのファイルを開いたアプリなど）を閉じる。閉じるものは画面の覚えでなく、自分の開いたコマンドから列挙する。残すと、ユーザーが自分の画面を片付けることになる。mac の Finder の窓は、Finder の `close` が効かない（-10010・-1708）ことがあり、System Events で窓の閉じるボタン（AXCloseButton）を押すと閉じる。
   - 自分が消えれば外せないので、外すまでは、鍵を置いていることと、この skill に従うことを引き継ぎ資料に書く。立ち上がり直したら、見込みの時刻のうちに外すか置き直す。同じフォルダのセッションが置いた鍵は、自分のものとして外せ、置き直せる。

### 環境ごとの注意

占有の間にユーザーがほかのマシンを使ってよいか、自動操作で避けることがあるかは、キーボードとマウスをほかのマシンと共有しているか（Deskflow などのソフトウェアの KVM）で変わる。利用者が `~/.claude/input-takeover-rules.json` に OS ごとに書く。Claude Code では mod が読み、`user` を了承のダイアログに、`agent` を鍵を置いた結果に出す。ほかのエージェントは自分で読み、手順1でユーザーに伝える（`agent` は自分で守る）。書いていなければ、このマシンのキーボードとマウスに触れないでもらうことだけを伝える。

```json
{
  "macos": {
    "machine": "mac の",
    "user": ["共有のキーボードとマウスに触れない（カーソルを隣のマシンへ移すと、自動操作の入力もそちらへ流れる）"],
    "agent": ["画面の下の端の行へカーソルを送らない（隣のマシンへ越える）"]
  }
}
```

- キーは `macos`・`linux`・`windows`・`wsl` と、どれにも当たらないときの `default`。`machine` は「〜の画面・キーボード・マウス」の前に付く語。`user` と `agent` は1要素が1行の文字列の配列。
- ほかのマシンの、入力を使わない操作には鍵が要らない。ssh でファイルを読む・コマンドの出力を見る・窓か範囲を指して画面を撮るなど。ssh でほかのマシンの入力を使う操作は、このマシンの鍵では守れないので、そのマシンのセッションに頼む。

### 鍵の限界

鍵は、かち合いを減らすだけで無くしはしない。鍵を見ないエージェントやユーザー自身の手元の操作には効かない。自動操作が理由の分からない失敗をしたら、かち合いをまず疑う。

合成の入力は、手の操作と同じには届かないことがある。macOS（CGEvent）と Wayland（Hyprland の wlr の仮想ポインター）では、WebView の外へのドラッグ（tauri-plugin-drag など）を続けて送ると、1回おきに始まらない（手では毎回効く。Windows の SendInput は続けても効く。2026-11-20 に確かめた）。macOS では、押し下げとドラッグのイベントに `kCGMouseEventClickState=1` を付けないと1回目から始まらない。この2つの OS で続けて送ったドラッグが失敗しても、アプリの不具合とみなさず、todo やコードの直しの前に、手か Windows で確かめる。

## Claude Code では

- 鍵は input-takeover の mod（この skill の `mod/`）のツール `mcp__input-takeover__input_takeover` で扱う。置くのは `{ action: "start", what, minutes }`、外すのは `{ action: "end" }`。セッションが終わると、mod が自分の鍵を外す。
- 手順3の知らせは、返答の文に加えて mod も出す（会話の1行・toast・OS の通知）。`end` で外したとき（見込みの時間を過ぎた後の `end` も）は、そのセッションが出す。セッションが終わって外したとき・落ちたときと、外されないまま見込みの時間を過ぎたときは、同じマシンで動いている対話のセッション（`-p` は除く）が鍵を見張って出す（時間切れは、持ち主が動いていれば持ち主がすぐ、ほかのセッションは1分後に。どれも1つのセッションだけが出し、10分より前のものは出さない）。時間切れの知らせは、操作が続いていることもあると添え、その後に持ち主が終わったらまた知らせる。ほかのセッションが鍵を置くときは、まだ知らせていない前の鍵の終わりを先に知らせる。
- `osascript`・`cliclick`・`screencapture`（窓か範囲を指して撮るだけのものを除く。同じコマンドで `open` を流すものは止める。見分ける選択肢は mod の `CAPTURE_TAKES_FOCUS`）・`xdotool`・SendKeys などは、自分の鍵が効いていないと mod が止める（立ち上がり直す前の鍵も、置き直すまでは自分のものとみなさない）。ほかのセッションの鍵が効いていれば、その持ち主と残りの分を添えて止める。鍵を確かめられない（`machine-locks` が隣に無いなど）ときも止める。
- 手順1の了承は、`start` が AskUserQuestion のダイアログで取る。ダイアログは通知が届くので、ユーザーが席を外していても気づける。問いには `what` と `minutes` と、占有の間にユーザーがしてよいこと・いけないこと（上の「環境ごとの注意」の `user`）が出る。作業に限った注意（このアプリの窓に触れない、など）は `notes`（1要素が改行の無い1行の文字列の配列）で足す。`notes` のある `start` は、下の10分のうちでも、同じ `what` の置き直しでなければ問う（問わないと注意が届かないため）。「始める」が選ばれたときだけ鍵を置き、ユーザーが手を離せるよう5秒待ってから返る。了承から10分のうちの `start` は、このセッションの鍵が効いていれば、問わず待たずに鍵を置き、効いていなければ（鍵を外した後・見込みの時間を過ぎて切れた後）問う（10分は了承した時から数え、使い続けても延ばさない。始める前の待ちを中断したときと、ほかのセッションの鍵で断られたときは、了承を残さない）。返答の文で先に問わず、そのまま `start` を呼ぶ（二度聞きになるため）。途中で出うる許可ダイアログとその答え方のように、問いに載らないことを伝えるときは、`start` を呼ぶ前の返答に書く。
- 断られた・閉じられたときは、`start` がユーザーの答えを添えて断るので、その答えに従う。このセッションの鍵が効いているうちの同じ `what` での置き直しは、10分を過ぎても問わない。立ち上がり直す前の鍵（同じフォルダのほかのセッションの鍵）の引き継ぎは、10分のうちでも問い直す。
- スクリプトの中で使うもの（`pnpm macos-check` など）は mod が見分けられないので、自分で鍵を置いてから流す。
- `open` は、頼まれたものか自分の判断かを mod が見分けられないので止めない。自分の判断で前に出すときは、自分で鍵を置いてから流す。

## ほかのエージェントでは

`machine-locks` の `scripts/locks.cjs` で鍵を扱う（`SKILL.md` の手順）。手順1の了承を自分で取ってから `acquire input --what <何をするか> --minutes <見込みの分> --same-root` で置き、`ok: false` ならその `heldBy` が外れるまで始めない。終わったら `release input --same-root` で外し、手順3の知らせを返答で伝える。

## 合格条件

- 人が見る: 置いた鍵を外し、始めることと外したことを返答の文でユーザーに伝えている。返したと伝えた後に、了承を取り直さずに奪い直していない。確かめのために開いた窓を閉じている。始める前に伝え、ユーザーの了承を受けてから始めている。
- 機械が見る: mod のテスト（`claude plugin test mod`）が通る。
