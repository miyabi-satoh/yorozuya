# 資源の鍵

同じマシンで複数のエージェントのセッションが動くと、キーボードとマウスや CPU を取り合って、互いの作業を壊す。資源ごとに1つの鍵をマシンに置き、鍵の効いている間はほかのセッションが始めないようにする。鍵を置くかどうか・何を止めるか・ユーザーに了承を取るかは資源ごとの方針で、それぞれの skill が決める（input は `input-takeover`、cpu は `heavy-task`）。この skill は、どの資源でも同じ鍵の扱いだけを受け持つ。

## 仕事

`scripts/locks.cjs` で、資源の鍵を置く・延ばす・外す・見る。

## やらないこと

- 鍵を置くかどうかを、ここで決めない — 了承や負荷の測り方は資源ごとに違い、それぞれの skill の手順にある。
- ほかのセッションの、効いている鍵を外さない — 持ち主の操作の途中を壊す。外れるのを待つ。

## 出力

鍵のファイル（`~/.claude/locks/<資源>.json`）の置き・外しと、`locks.cjs` の答え（JSON 1行）。

## 終わる条件

方針の skill が求めた操作（置く・外す・見る）の答えを受け取ったとき。

## 止まる条件

次のときは推測で埋めずに止まり、ユーザーに聞く。

- 必要な情報が分からないとき: ほかのセッションの鍵が、延ばされ続けて外れないとき。
- 承認が要る操作の手前: `locks.cjs` が 1 で終わり、鍵を扱えないとき（取り合いのファイル `<資源>.json.mutex` が残る、など。中の pid のプロセスが鍵を扱っていなければ、ユーザーの了承を得て消す）。鍵を確かめないまま始めない。

## 手順

1. 方針の skill の手順のとおりに、`node <この skill>/scripts/locks.cjs <操作> <資源> ...` を流す。どれも JSON を1行出す。
   - `status <資源>`: `state`（`free`・`held`・`expired`・`dead`）、効いている鍵 `lock`（無ければ `null`）、置かれたままの鍵 `last`、その持ち主が生きているか `alive`。
   - `acquire <資源> --what <何をするか> --minutes <見込みの分>`: 置けたら `ok: true`。ほかのセッションの鍵が効いていれば `ok: false` と、その鍵 `heldBy`。自分の鍵が効いていれば置き直して延ばす。
   - `release <資源>`: 自分の鍵を外し、外した鍵 `released` を返す（無ければ `null`）。見込みの時刻を過ぎた自分の鍵も外す。
   - `clear <資源>`: 効いていない鍵（切れたもの・持ち主が落ちたもの）を消す。
2. 自分を見分ける `--session` を付ける。Claude Code の中では、無くても `CLAUDE_CODE_SESSION_ID` を使う。ほかのエージェントは、そのセッションで変わらない文字列を自分で決める。
3. 立ち上がり直す前の自分の鍵を引き継ぐ資源（input）では、`acquire`・`release` に `--same-root` を付ける。同じ作業フォルダ（`--root`。無ければ今のフォルダ）のセッションの鍵を、自分のものとして置き直せる（引き継ぐ前にユーザーの了承を取り直すのは、方針の skill の手順）。外せるのは、その持ち主が生きていると分からないときだけ（同じフォルダで動くほかのセッションの、操作の途中の鍵は外さない）。

鍵が外れたとみなされるのは、外したとき、見込みの時刻を過ぎたとき、持ち主の Claude Code のプロセスが無くなったときのどれか。持ち主が外さずに落ちても、ほかのセッションは待ち続けずに済む。ほかのエージェントの鍵は、プロセスを見分けられないので、見込みの時刻で外れる。

## 合格条件

- 人が見る: ほかのセッションの効いている鍵を、外したり上書きしたりしていない。置いた鍵を、終わったときに外している。
- 機械が見る: `node --test scripts/locks.test.cjs` が通る（取り合い・持ち主が落ちたとき）。
