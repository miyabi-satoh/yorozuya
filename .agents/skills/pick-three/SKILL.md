# 並べて見比べて選んでもらう

## 仕事

文章で一問ずつ聞くより見渡したほうが選びやすい判断について、案を1枚のページに並べ、ユーザーが選んだ案と理由を受け取って作業を続ける。人は並べた差を見比べるのは一瞬でできるが、ターミナルの文章では前の問いや案を覚えたまま読み比べることになり、全体が見えないため。

- 見た目の判断は、違いのはっきりした3案を作る。1つの案の良し悪しや、多すぎる案からは選びにくいため。
- 選択肢の多い決定・絡み合う決定は、出所にある選択肢や決定をそのまま並べる。数を3つにそろえるために案を作ったり削ったりしない。

## やらないこと

- 数行の文章で比べ終わるもの（二択・1つの値で決まるものなど）でページを作る — 並べる材料が無く、ページを開く手間だけが増える。損得を添えて推奨を返す。見た目に出ない設計（データの持ち方・API の形など）でも、比べる項目が多ければページの表にする。
- 一般的な形が1つに決まっているもの（よくある入力欄・定番の確認ダイアログなど）で3案を作る — 1案と拠り所で足りる。
- 細部だけが違う案を並べる — 差が見えず選べない。配置・構成・語の選び方など、方針の違うものにする。
- 案を作る前に、拠り所を飛ばす — 案はどれも拠り所（よく知られたアプリの作法・プロジェクトの既存の画面・用語の決めごと）に沿わせる。利用者の指示ファイルや skill に UI の好みや拠り所が書いてあれば、それにも沿わせる。

## 出力

- 案を並べたページ1枚。同じ作業で判断がいくつも出たら、1枚に並べて一度に選んでもらう（絡み合う決定は、1つを選ぶと残りがどう変わるかも見えるようにする）。
  - Claude Code で Artifact ツールが使えるなら、アーティファクトとして出す。選んだ案と一言の理由を残す欄を置き、結果は `db` の機能に残して `ArtifactData` で読む。作る前に `artifact-design` と `artifact-capabilities` の skill を読む。
  - アーティファクトを出せないエージェントでは、HTML ファイルを作ってブラウザーで開き、選んだ案はチャットで返してもらう。
- 選ばれた案と理由を、そのプロジェクトの決めごと（`docs/ui.md`・用語の表・`decisions.md` など、プロジェクトが決めた置き場）に書いたもの。次に同じ種類の判断が出たとき、3案を出さずに済ませるため。

## 終わる条件

ユーザーが案を選び、選んだ案で作業を続け、その判断を決めごとに書いた。

## 止まる条件

次のときは推測で埋めずに止まり、ユーザーに聞く。

- どの案も、ユーザーの条件や拠り所に合わないと分かったとき: 合う案が作れない理由を添えて、条件を確かめる。
- 選ばれた案が、既存の決めごとと食い違うとき: 決めごとのほうを書き換えるかを確かめる。

## 手順

1. 何を選んでもらうのかを1文で決める（例:「削除の確認ダイアログで、使われているテンプレートの警告をどこに出すか」）。ページの見出しにする。
2. プロジェクトの決めごとに、同じ種類の判断が既に書かれていないかを見る。書かれていれば、3案を作らずにそれに従う。
3. 案をそろえる。見た目の判断は、違いのはっきりした3案にし、1つは一般的な形（よく知られたアプリの作法）、残りの2つは方針を変える。選択肢の多い決定・絡み合う決定は、決定ごとに出所の選択肢を並べ、比べる軸（範囲・数・出所の数など）を表や図でそろえる。
4. 案の見せ方は、作る手間の安い方を選ぶ。
   - 目安として、新しい画面は静的な HTML で再現する（動くコードがまだ無い）。
   - 今ある画面の手直しと、今ある画面に要素や機能を足す案は、実物を3通りに直してスクリーンショットを撮る（データや状態の作りが既にあり、HTML で作り直すと手間がかかるうえ実物とずれる）。撮るのはブラウザーの自動操作（Playwright など）で。HTML で作るしかないときも、今の画面を写した上で、変わるところだけを案ごとに変える。今の画面と見た目が違うと、何がどう変わるのかが読めない。
   - 文言だけの判断は、実際の画面の文脈（前後の項目・ボタン）に置いた形で見せる。文言だけを並べると、画面での読まれ方が分からない。
5. 案を横に並べ（狭い画面では縦。決定がいくつもあれば決定ごとの段に分ける）、それぞれに短い名前と、ほかの案との違い・損得を1〜2行で添える。推奨を1つ示す（決定がいくつもあれば決定ごとに）。
6. ページを出し、返答の末尾で、ページを見て選んでほしいことを伝えてターンを終える。
7. 選ばれた案と理由を読み、その案で作業を続ける。理由が推奨と違えば、何を重く見たのかを読み取って、残りの作業にも当てる。
8. 選ばれた案と理由を、プロジェクトの決めごとに書く。

## 合格条件

- 人が見る: 案が方針の違うものになっていて、ひと目で差が分かる。決定がいくつもあれば全体を1枚で見渡せる。どの案も拠り所に沿っている。推奨が判断ごとに1つある。選ばれた結果が決めごとに書かれている。
- 機械が見る: 無い。
