# 自分自身を再起動する

context-watch の mod から `OVER`・`UPDATE`・`UPDATE FAILED` の知らせが来たときも、この手順で再起動する。

**依頼された仕事を終えていれば、再起動せずに終わる。** 仕事を終えて報告も済ませていて、[exit-self.md](exit-self.md) の終わらない条件に当たらなければ、再起動の代わりに exit-self.md で終わる。立て直しても、新セッションは引き継ぐ仕事が無く、`after-restart.md` に従って終わるだけになるため。`exit-self.mjs` は hc の端末でだけ動くので、Herdr のペインでは試さずにこの手順で再起動する。hc の端末で SKIP・FAIL を返して終われなければ、exit-self.md のとおりに扱い、それでも終われなければこの手順で再起動する。

`scripts/restart-self.mjs <資料の絶対パス>` を使う。新ペインの Herdr 名は、旧ペインが持っていた名前を引き継ぐ（名前が無ければ cwd のフォルダー名から作る。変えたいときは2つ目の引数で渡す）。**手順を持つのは生き残る側**（新セッション）。
死ぬ側が `/exit` を送るとスクリプト自身も消えるため、依存を逆転させてある。
旧ペインを閉じるのも報告するのも新セッション。
hc の端末では、同じ cwd に新しい端末を作って claude を起動し（依頼は claude の引数で渡す）、旧の端末は新セッションが `hc kill`・`hc rm` で閉じる。hc は名前を付け替えられず、旧の端末が生きている間は同じ名前を使えないので、新しい端末の名前は `<名前>-2`（`-2` で終わる名前なら外した名前）になる。2つ目の引数で渡せばその名前にする。

呼ぶ前に**資料を自分で用意する**。SKILL.md の「手順」の2〜4と同じ形（状態メモ＋会話ログ）を、返信を待たずに自分で作る。

1. 自分のセッションIDを控える。Bash の環境変数 `$CLAUDE_CODE_SESSION_ID`、または `herdr pane current --current` の `agent_session.value`（UUID の形。hc では `hc get "$HC_TERMINAL_ID" --json` の `foreground.pid` と同じ `pid` の、`claude agents --json` の `sessionId`）。`ListAgents` の先頭行の `[xxxxxx]` は送り先を見分ける短い印で、セッションIDではない。
2. `scripts/extract-transcript.mjs <自分のセッションID> --out <出力先>` で、自分の会話ログを抜き出す。
3. 資料の先頭に状態メモを書く。SKILL.md の「手順」の2の依頼文に入れる内容（状態: 作業の途中・ユーザーの答えや操作の待ち・指示待ちのどれか。答えや操作の待ちなら問いや頼んだ操作の文面と選択肢をそのまま。バックグラウンド処理の立ち上げ直し手順。全体の流れの置き場と今の作業の位置。置き場のずれの扱いも SKILL.md の「手順」の2と同じ）に加え、**引き継ぎ先は検証役でもある**ので「何を確かめてほしいか」も書く。旧セッションは死んでいて自分では確かめられないため。進め方（`after-restart.md`）はスクリプトが資料の前につないで渡すので、資料には足さない。答えや問いを出し直すかも進め方が決めるので、「出し直さなくてよい」とは書かない。
4. 状態メモに続けて、抜き出した会話ログを結合する。これが資料になる。**会話に出た秘密情報は、抜き出した資料にもそのまま残る。** 心当たりがあれば渡す前に見て消す。

**呼んだら黙って止まる。** 成功（終了コード 0）なら、それ以上何も出力しない。
報告も要約も別れの言葉も要らない。
旧ペインは資料を読み終えた新セッションに閉じられるので、書いても誰にも読まれないまま消える。
ユーザーへの報告は新セッションの仕事。
**終了コード 1（SKIP でも FAIL でも）のときは報告する。** そのときは旧セッションが生き残っていて、伝えられるのはこちらしかいない。

**呼ぶ前に、自分のバックグラウンドの処理が残っていないことを確かめる。**
ペインごと閉じて強制終了するので、走っているものは巻き添えになる。
他セッションの再起動の最中に自分を殺すと、対象が `/exit` と起動の間で取り残される。
コンテキストの見張りを走らせているなら TaskStop で止め、走らせ直すコマンド（引数で `config.local.json` の値を上書きしていれば、その引数も）を資料に書く。
再起動を依頼して返信を待っているセッションと、「止められない」と返してきたセッションも書く。張り直した見張りは同じ知らせをもう一度出すので、新セッションが捨てるかを決める材料になる。

`restart-self.mjs` も、自分のモードラインにシェル・Monitor が見えていれば SKIP する。**自分の記憶も当てにしない。**
見張りを止めたつもりでも、TaskStop を忘れていたり、別のバックグラウンドシェルが残っていたりしうる。
SKIP になったら、TaskStop や `jobs` 相当の確認をやり直してから呼び直す。`--allow-background` を付けるのは、ペインを閉じても動き続けると確かめた独立したプロセスだけ。Monitor やバックグラウンドのシェルはペインと一緒に止まるので、新セッションには引き継げない（見張りは新セッションの SessionStart hook と資料で改めて始まる）。

SKIP・FAIL のときの対処と、SKILL.md の「手順」の6にあたる確かめをスクリプトが行うことは、SKILL.md の「詰まったとき」「知っておくこと」にある。
