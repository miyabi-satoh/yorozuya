# コンテキストを見張る

**mod を読み込ませていれば、各セッションが自分を見張る**（`mod/`。読み込ませ方は README の「使い方」の3）。ほかのセッションを外から見張る下のスクリプトは要らない。

- ターンの終わりに、自分の使用率（`$.session.usage()`）が `config.local.json` の `watch.threshold`（無ければ 50）以上なら `OVER`、入っている Claude Code（`claude --version`）が動いている版と違えば `UPDATE` を、自分へのメッセージで知らせる。受けたセッションは [restart-self.md](restart-self.md) で自分を再起動する。ターンの終わりは区切りなので、区切りを尋ねる依頼と返信は要らない。
- 最後の応答から75分たち、コンテキストが10万トークン以上なら、モデルのターンを使わずに `scripts/idle-clear-self.mjs` で自分のペインを `/clear` し、抜き出した会話ログを読ませる（[idle-clear.md](idle-clear.md) を自分に当てる形）。idle でない・入力欄に書きかけがある・バックグラウンドの処理が動いているときは見送り、10分後に見直す。
- `/goal` が動いている間と、Herdr の外では何もしない。知らせはセッションごとに1回。

以下は、mod を使わずにほかのセッションを外から見張るとき。

`scripts/watch-context.mjs` が各 claude ペインのステータスラインから使用率を読み、閾値以上になったセッションを1行で知らせる。
Claude Code の更新の知らせ（再起動で反映される）と、「放置から戻ったときのヒント」（`new task? /clear to save …`）が出ているセッションも、それぞれ1行で知らせる。
知らせは聞きに行くきっかけにすぎない。区切りの判断は、いつもどおり対象がする。

**前提。** ステータスラインにコンテキストの使用率が出ていること。出ていなければ見張れない。

**設定。** 使う人ごとに違う値は、スキルのディレクトリの `config.local.json`（git 管理外。形は `config.example.json`）に置く。

- `confirm` — `true` なら、知らせのたびに再起動や `/clear` に進んでよいかをユーザーに確認する。既定は `false`（確認なし）。
- `watch` — 見張りの引数を、下の表の名前（`--` を外したもの）で書く。優先順は、引数 → `watch` → 既定。

**引数。** `--pattern` のほかは省ける。`--pattern` はステータスラインの表示しだいで誰にでも合う既定が無いので、引数か `watch.pattern` で必ず渡す。無ければ見張りは始まらない。

| 引数 | 既定 | 役割 |
|---|---|---|
| `--pattern` | 無し | 使用率の数字を1つ目のキャプチャで取る。入力欄の下枠より下の数行（ステータスライン）だけに当てる。照合の前にノーブレークスペース（U+00A0）を普通の空白に揃えるので、空白は普通の空白で書く。ccstatusline の `Ctx Used: 12.3%` なら `'Ctx Used: ([\d.]+)%'` |
| `--threshold` | `30` | この使用率（%）以上で `OVER` を出す。使用率なので、コンテキストの上限が小さいモデルほど少ないトークンで出る |
| `--interval` | `120` | ペインを読む間隔（秒） |
| `--update-pattern` | `'Update installed'` | 更新の知らせの文言（2.1.272 の知らせは「Update installed · Restart to update」か「… Restart to apply」）。入力欄の上枠のすぐ上の1行だけに当てるので、会話に同じ文言が出ても拾わない |
| `--idle-pattern` | `'new task\?'` | 放置のヒントの文言。`--update-pattern` と同じ1行に当てる。ヒントは、コンテキストが 10万トークン以上で、最後の応答から 75 分たつと出る（2.1.278 のコードで確認。環境変数 `CLAUDE_CODE_IDLE_TOKEN_THRESHOLD`・`CLAUDE_CODE_IDLE_THRESHOLD_MINUTES` で変わる） |
| `--goal-pattern` | `'/goal active'` | `/goal`（自律的な目標追従モード）が動いている間かどうかの文言。`--update-pattern` と同じ1行に当てる。動いている間は OVER・UPDATE・IDLE をどれも出さない（区切りの確認で割り込むと目標追従を途中で止めることになるため）。通知先には加えないので、`/goal` が外れれば次の tick で改めて判定される。表示の経過時間に上限は無く、長く動き続けるならその間は黙り続ける |
| `--no-update` | off | 更新の知らせを見ない |
| `--no-idle` | off | 放置のヒントを見ない |
| `--no-goal` | off | `/goal` 中の抑制を見ない |
| `--start` | off | 最初に読めた回に `START` の行を出す（下の「始める」の 2） |
| `--once` | off | 1回読んで終わる（試運転用） |

**始める。**

1. 知らせは、既定では確認なしで流す。`config.local.json` の `confirm` が `true` なら、知らせのたびに確認する（hook が起動時に差し込む文に入っている）。
2. `--start --once` を付けて当て、`START` の行で全ペインが読めているか確かめる。列は `閾値 読めた数/claude ペインの数 名前=使用率 …`。読めないペインは `名前=?`、`blocked` のペイン（承認や選択式の問いの待ち）は `名前=blocked` と並び、どちらも読めた数に入らない。`/goal` が動いているペインは `名前=goal` と並び、読めた数に入る。全部読めなければ `--pattern` が表示に合っていない。どれか1つのペインを `herdr pane read <pane> --source visible` で読み、合うものを作ってユーザーに示し、`watch.pattern` に書いてもらう。Herdr の一覧が取れなければ、`START` の代わりに `WARN` が出て終了コードが 1 になる。
3. `mcp__context-watch__start` ツールがあれば（`mod/` を読み込ませたとき）、それを呼ぶ。見張りはセッションの間ずっと動き、知らせは context-watch プラグインからのメッセージとして届く。張り直しは要らない。mod を読み直すと見張りも立ち上がり直し、閾値以上のままのセッションにもう一度知らせが出る（下の「知らせが来たら」の張り直しと同じ扱い）。
   ツールが無ければ Monitor で走らせる。Monitor は最長 30 分で切れるので、`timeout_ms` を上限にし、切れたら同じコマンドで張り直す。張り直したことは、その時点の時刻を添えてユーザーに伝える（次に切れる目安になる）。時刻は `date '+%H:%M'`（PowerShell なら `Get-Date -Format HH:mm`）などで取る。
   ```
   node <このスキルのディレクトリ>/scripts/watch-context.mjs
   ```
   `START` を出さないのは、張り直すたびに起こされないため。**`| grep -v '^START'` で落とさないこと。** Claude Code のシェルでは `grep` が組み込みの ugrep を呼ぶシェル関数に差し替わっていて、走りっぱなしの入力では行を溜め込み、`OVER` も `UPDATE` も Monitor に届かなくなる（`--line-buffered` を付けても同じ。2026-09-20 に実測）。

引数を変えたいときは、そのときの依頼で渡す。恒常的に変えたい値（閾値など）は `config.local.json` に置く。
起動のたびに始めるには、使う側の `.claude/settings.json` に SessionStart（matcher: `startup`）の hook を置く（置き方は README の「使い方」）。hook は `scripts/session-start.mjs` を呼び、走らせるコマンド（絶対パス）・確認の要否・「すでに走らせていれば二重に始めない」旨を会話に差し込む。`config.local.json` が無い・誤っているときは、見張りを始めずにその旨をユーザーに伝えさせる。hook を置いたプロジェクトで複数のセッションを起動したり、複数のプロジェクトに hook を置いたりすると、どれもが見張りを始め、同じ知らせで二重に動く（見張りはマシンの Herdr 上の claude ペインすべてを見る）。見張りは1つのセッションだけに持たせ、ほかは止める。hook から Monitor は呼べないので、始めるのは最初に返事をするときになる。matcher を `startup` にした hook は、再開（resume）したセッションでは動かなかった（matcher に `resume` を足せば動くかは未確認）。

**知らせが来たら。**

- `OVER` — 列は `使用率 pane_id Herdr名 端末タイトル セッションID cwd`。SKILL.md の「手順」の1から進める（ペインIDは使う直前に引き直す）。既定では名指しの指示と同じに扱い、確認なしで進める。`confirm` が `true` なら、再起動してよいか聞く。
- `UPDATE` — 列は `知らせの行 pane_id Herdr名 端末タイトル セッションID cwd`。`OVER` と同じに扱う。依頼文の理由は「Claude Code の更新を反映するため」とする。
- `IDLE` — 列は `ヒントの行 pane_id Herdr名 端末タイトル セッションID cwd`。放置で大きくなった会話を `/clear` して続ける機会。**対象に資料を書かせない**（書かせた時点で、冷えたキャッシュに大きな会話を読み直させる割高なトークンが出るため。ユーザーの判断）。[idle-clear.md](idle-clear.md)（放置のあとの `/clear`）に進む。
  ヒントが出ているペインには、見張りが `OVER`・`UPDATE` を出さない（`IDLE` だけ）。`/clear` で会話が消えるので `OVER` は無意味になり、`UPDATE` は新しいセッションで改めて出る。
- `/goal` が動いているペインは、`OVER`・`UPDATE`・`IDLE` のどれも出ない（表示は `名前=goal`）。外れるまで待つ。長く動き続けるなら、その間は黙り続ける。
- 対象が自分自身なら[restart-self.md](restart-self.md)（自分自身を再起動する）に進む。
- 知らせを扱う前に、ペインのセッションIDを引き直す。知らせのIDと違えば再起動は済んでいるので、捨てる（同じセッションに `OVER` と `UPDATE` が両方来たときなど）。IDの列が `-`（取れなかった）なら、pane_id と端末タイトルで照合する。
- `OVER` と `UPDATE` は、1つの見張りのプロセスからは同じセッションに1回しか出ない。張り直すと、閾値以上のままのセッションや知らせが出たままのセッションにもう一度出る。再起動を依頼して返信を待っているセッションなら捨てる。対象が「止められない」と返したら SKILL.md の「詰まったとき」のとおりにし、改めて依頼するのは対象からの返信かユーザーの指示を受けてから。
- `WARN` — 使用率を3回続けて読めないペインがある、または Herdr の一覧が取れない。ユーザーに伝える。`blocked` のペイン（承認や選択式の問いの待ち）はダイアログがステータスラインを隠すので、読めなくても数えない。Herdr が `blocked` と返さない選択式の問い（Herdr 0.9.1 の AskUserQuestion）も、画面の末尾の数行に `Esc to cancel` があれば数えず、`名前=blocked` と並べる。ステータスラインの形が変わったなら `--pattern` を作り直して走らせ直す。入力欄の見えない画面（トランスクリプト表示など）も読めない扱いになるので、ペインを見て確かめる。
- 再起動の最中に別の知らせが来たら、今の再起動を終えてから順に扱う。
