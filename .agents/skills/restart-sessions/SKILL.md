description: Herdr 上の Claude セッションを、handoff を取ってから再起動する。ユーザーがペインの再起動を頼んだとき、自分のコンテキストが増えて自身を立て直すとき、対象から増加の申告があったとき、コンテキストの見張りから知らせが来たときに使う。
---

再起動の目的は、コンテキストが枯渇して性能が落ちる前に、handoff を取って新しいセッションに移ること。

**判断はこのセッションが持つ。** スクリプトが引き受けるのは、後戻りできない連鎖（`/exit` から資料を読ませるまで）と、聞きに行くきっかけを出すだけの見張り（「コンテキストを見張る」）。
対象の状態は画面から読み取らず、**対象に聞く**。返信は自動で届く。
画面から読むのは、聞きに行くきっかけと、聞いても届かないとき（依頼が送信されずに残っている、ダイアログで止まっている）にとどめる。

## 手順

1. `herdr agent list` で対象のペインIDと Herdr の名前を引く。
   `ListAgents` で自分の名前を引く（`yorozuya-XX` の XX はセッションごとに変わる。引き継ぎ資料の名前は使わない）。

2. 依頼を**ペインに打ち込む**。
   ```
   herdr agent prompt <pane> "/mattpocock-skills:handoff <依頼文>"
   ```
   handoff スキルは `disable-model-invocation` で、メッセージからは呼べない。
   だから依頼だけは入力欄に打ち込む。**結果は打ち込まず、相手に返信させる。**

   依頼文に入れること。
   - 再起動の理由と、再起動後も同じプロジェクトで作業を続けること
   - 区切りまで終えてから書くこと（途中で判断が要るならユーザーに聞く）
   - 資料の冒頭に、再起動の依頼を受ける前の状態を書くこと。作業の途中（ユーザーの新しい指示が無くても次の一手に進むつもりだった。何をどこまで済ませ、次に何をするか）、ユーザーの答えや操作の待ち（ユーザーへの問いや頼んだ操作の文面と選択肢をそのまま。ダイアログで聞いたかテキストで聞いたかも）、指示待ち（次に何をするかをユーザーが決める）のどれか。新セッションはこれを読んで、再開するか、同じ問いで待つか、そのまま待つかを決める
   - このプロジェクトの全体の流れの置き場（roadmap の文書・外部のノートのページ・issue など、形は問わない）と、今の作業がその中のどこにあたるかを資料に書くこと
     - 置き場の中身が今の状態とずれていれば、直してから資料を書く。置き場への書き込みが外向きの操作になるなら（issue・外部のノートなど）、そのプロジェクトの決まりどおりに確かめる。直せなければ、ずれを資料に書く
     - 置き場が CLAUDE.md・AGENTS.md・記憶から辿れなければ、辿れる1行を足す（足してよいかはユーザーに聞く）。公開しているリポジトリで置き場が非公開なら、公開するファイルではなく、CLAUDE.local.md や記憶に足す
     - 全体の流れと呼べるものが無い規模なら書かなくてよい。流れはあるのに置き場が無ければ、ユーザーに置き場を聞く
   - 再起動でバックグラウンドの処理はすべて止まる。立ち上げ直せばよいものは手順を資料に書き、書き終えたら自分で止めること
   - **資料を書いたら、絶対パスを添えて `<自分の名前>` に返信すること**
   - 今止めるとまずい処理が走っているなら、資料を書かずにその旨を返信すること

   全体の流れを置き場に書かせるのは、handoff スキルの資料が今の会話の要約だから。
   会話に出てこなかった大きな流れ（中長期の作業のうち、今のセッションが触れていない部分）は資料に入らず、置き場に無ければ再起動のたびに細る。
   置き場の形はプロジェクトの規模で違うので決め打ちしない。

   **打ち込んだコマンドは、対象のターンが終わるまで持ち越される。** 普通のメッセージと違い、ツール呼び出しの切れ目では渡されない。
   対象が `working` なら、続けて `SendMessage` で「handoff の依頼が入力欄で待っている。区切りでターンを終えてほしい」と知らせる。
   SendMessage はツール呼び出しの切れ目で読まれるので、長く続くターンにも届く。
   ただし1回の長いツール呼び出し（前景のサブエージェント待ちなど）の最中は、これも届かない。

3. 返信を待つ。**ポーリングしない。** 返信は自動でこの会話に届く。
   何も返ってこないまま気になるなら `SendMessage` の `notify_when_idle` を使う。

4. 返ってきたパスのファイルがあることを確かめる。無ければ対象に聞き直す。

5. `scripts/restart.mjs <pane> <name> <資料の絶対パス>` を実行する。
   終了・起動・読み込みを一息で行う。**ターンをまたがせない。**

6. 資料を読ませる依頼（`@<資料> 前セッションの引き継ぎ資料です。…`）が送信されたかを確かめる。`OK` は、Herdr が依頼の文と Enter を送ったところまで。claude が受け取って動き出したかは見ていない。Enter だけが落ちて、依頼が入力欄に残ったことがある（原因は分かっていない）。
   ```
   herdr agent wait <name> --until working --until blocked --timeout 30000
   ```
   返ったもので分ける。
   - `working` — 資料を読み始めている。手順7へ。
   - `blocked` — `herdr agent read <name> --source visible` で画面を読む。新セッションが出した問い（選択式の問い）や、ツールの実行の許可なら、依頼は送信されている。手順7へ。起動の時に出るダイアログ（フォルダの信頼、MCP サーバーの承認など）なら、依頼は送信されていないかもしれない。Enter を送らずにユーザーにペインを見てもらう。
   - `timeout` のエラー — `herdr agent read <name> --source visible --format ansi` で画面を読む。入力欄が空か薄字（`ESC[2m`）のサジェストだけで、資料を読んだ応答が会話に出ていれば、依頼は送信されている（指示待ちの新セッションは、短いターンで `idle` に戻る）。手順7へ。そうでなければ、次の両方に当てはまるときだけ、`herdr agent send-keys <name> Enter` で送り、もう一度待つ。
     - 入力欄にあるのが依頼の文だけで、薄字（`ESC[2m`）のサジェストではない。長い依頼は末尾しか見えない
     - 候補のメニューも、ダイアログや選択式の問いも出ていない

   どれにも当てはまらないとき（入力欄が上の条件に合わない、2回目も時間切れ、ほかのエラー）は、Enter を送らずにユーザーにペインを見てもらう。

7. 結果を報告する。旧セッションID は `resume:` として出力の末尾に出る。

## 判断の基準

**区切りかどうかは対象が決める。** 依頼文に「区切りまで終えてから」と書き、あとは待つ。
`idle` は「入力を待っている」だけで作業の区切りとは別物（返事待ちを4件抱えたまま idle だった例がある）。

**返信の形を決めつけない。** 「READY」とだけ返す相手もいれば、報告を添える相手もいる。
読んで判断する。過去に申告の形を1つに決めつけて、拾えないまま黙って待ち続けた事故がある。

**名指しの指示はそのまま流す。** ユーザーが「このセッションを再起動して」と言ったら、それが承認にあたる。
確認を取り直すのは、こちらから提案するときだけ。

**対象がテキストの問いかけを表示したまま止まっていても進める（`agent_status` が `idle` のもの）。** ユーザーは問いの存在を承知のうえで指示していることがあり、「先に答えますか」と聞き返せば答える方向へ誘導することになる。宙に浮いた問いかけは資料に残り、新セッションが出し直す。

**ただし選択式の問いや承認ダイアログ（`blocked`）は別。**（再起動した新セッションが出し直した選択式の問いもこれに当たる） Herdr が `agent prompt` を弾くので依頼そのものが届かない。スクリプトも pre-flight で止まる。ユーザーにペインで答えてもらう。

## 詰まったとき

- **対象が「止められない」と返してきた** — 旧セッションは無傷。理由をユーザーに伝えて終わる。その処理が済んでから改めて提案する。
- **返信が来ない** — 依頼は届いている。後から返ってくることがある。急ぐならペインを見る。
  依頼が入力欄の下にキューとして残っていれば、対象のターンがまだ終わっていない。急ぐならユーザーにペインで Esc を押してもらう（ターンが止まり、キューの中身がすぐに送られる）。
- **FAIL で確認画面** — `/exit` の後の終了確認はユーザーにペインで選んでもらう。終了した後の戻り方はメッセージに書いてある。
- **FAIL で `/exit` を送った後に止まった** — claude が終了してシェルに戻った後は、**同じ引数で再実行しても通らない。** エージェントのいないペインは pre-flight で SKIP になる。メッセージに書いてある手順で手で起動し直す（名前が外れたのを確かめてから `herdr agent start`、起動したら `@<資料>`。または `claude --resume <ID>` で元の会話）。確認画面でキャンセルして claude が動き続けているなら、何も変わっていないので再実行できる。
- **対象が `blocked` で依頼が届かない** — 直前の再起動で新セッションが出した問い（出し直した問いや、状態を聞く問い）や、再開した作業の権限の確認に、まだ答えていないことがある。ユーザーにそのペインで答えてもらってから、手順1からやり直す。
- **FAIL で起動の段が `agent_pane_busy`** — `/exit` の後にシェルへ戻ったのを確かめてから起動しているので、旧セッションは終わっている。Herdr がそのペインをまだ使用中と見ているだけ。**まずペインを見る。** claude が上がっていれば、確認やダイアログが出ていないか見て、出ていれば答えてもらってから `@<資料>` を渡す。シェルのプロンプトに戻っていれば、メッセージに書いてある手順（名前が外れたのを確かめてから `herdr agent start`、起動したら `@<資料>`）で起動し直す。
- **SKIP で止まった** — まだ何も変えていない。メッセージのとおりに直して再実行する。資料は絶対パスで空白なし、名前は Herdr の規則（先頭は小文字・英数と `_` `-`・32字以内）、ペインIDと名前は `herdr agent list` で引き直したものであること。
- **FAIL で「新ペインは開いたまま残した」（自己再起動）** — 起動が失敗した。信頼ダイアログや確認がそのペインに出ていないかユーザーに見てもらう。答えてもらったら、**必ず先にそのペインを閉じてから**同じ引数で呼び直す（閉じずに呼び直すとペインが増える）。ペインを閉じないのは、答えようとした画面を消さないため。
  メッセージには Herdr 名の状態も書いてある。「握ったままで、外せなかった」と出ていたら、**生きているこのセッションが無名で、名前は残した新ペインを指している**。書かれた順に手で戻す（まず新ペインの名前を `--clear`、通らなければペインを閉じて名前が外れるのを待ってから旧ペインに付け直す）。閉じた直後は名前の解放に数秒かかるので、呼び直しで「名前 … が使用中」の SKIP が出たら少し待ってもう一度。
- **FAIL で「ペインは分割できたが ID を読み取れない」（自己再起動）** — Herdr の出力の形が変わった可能性。新ペインが残っているので手で閉じる。閉じずに呼び直すとペインが増える。
- **SKIP で「ペインの cwd を取れない」（自己再起動）** — Herdr が cwd を返さなかった。`herdr pane current --current` で Herdr 側の状態を確かめる。

## コンテキストを見張る

`scripts/watch-context.mjs` が各 claude ペインのステータスラインから使用率を読み、閾値以上になったセッションを1行で知らせる。
`--update-pattern` を渡せば、Claude Code の更新の知らせ（再起動で反映される）が出ているセッションも知らせる。
知らせは聞きに行くきっかけにすぎない。区切りの判断は、いつもどおり対象がする。

**前提。** ステータスラインにコンテキストの使用率が出ていること。出ていなければ見張れない。

**始める。**

1. 閾値と、更新の知らせも見るかと、知らせが来たら確認なしで流すかを、ユーザーに聞く。記憶機能に決まった値があればそれを使う。
2. どれか1つのペインを `herdr pane read <pane> --source visible` で読み、使用率の表示に合う `--pattern` を作る。使用率の数字を1つ目のキャプチャで取る（例: `'Ctx Used: ([\d.]+)%'`）。スクリプトはパターンを、入力欄の下枠より下の数行（ステータスライン）だけに当てる。照合の前にノーブレークスペース（U+00A0）を普通の空白に揃えるので、パターンの空白は普通の空白で書く。
3. 更新も見るなら、知らせの文言に合う `--update-pattern` を作る（例: `'Update installed'`。2.1.272 の知らせは「Update installed · Restart to update」か「… Restart to apply」）。
   知らせは入力欄の上枠のすぐ上の行に右寄せで出るので、スクリプトはその1行だけに当てる。会話に同じ文言が出ても拾わないためで、パターンは文言だけ合わせればよい。
4. `--once` を付けて当て、`START` の行で全ペインが読めているか確かめる。列は `閾値 読めた数/claude ペインの数 名前=使用率 …`。読めないペインは `名前=?`、`blocked` のペイン（承認や選択式の問いの待ち）は `名前=blocked` と並び、どちらも読めた数に入らない。Herdr の一覧が取れなければ、`START` の代わりに `WARN` が出て終了コードが 1 になる。
5. Monitor で走らせる。Monitor は最長 30 分で切れるので、`timeout_ms` を上限にし、切れたら同じコマンドで張り直す。張り直したことは、その時点の時刻を添えてユーザーに伝える（次に切れる目安になる）。時刻は `date '+%H:%M'`（PowerShell なら `Get-Date -Format HH:mm`）などで取る。
   ```
   node <このスキルのディレクトリ>/scripts/watch-context.mjs --pattern '<パターン>' --threshold <閾値> [--update-pattern '<パターン>']
   ```

閾値・パターン・確認の要否は環境ごとの値なので、このリポジトリには書かず記憶機能に置く。
起動のたびに始めたいなら、`.claude/settings.local.json` に SessionStart（matcher: `startup`）の hook を置き、走らせるコマンドと「すでに走らせていれば二重に始めない」旨を会話に差し込ませる。hook から Monitor は呼べないので、始めるのは最初に返事をするときになる。matcher を `startup` にした hook は、再開（resume）したセッションでは動かなかった（matcher に `resume` を足せば動くかは未確認）。

**知らせが来たら。**

- `OVER` — 列は `使用率 pane_id Herdr名 端末タイトル セッションID cwd`。「手順」の1から進める（ペインIDは使う直前に引き直す）。ユーザーが確認なしで流すと決めていれば名指しの指示と同じに扱い、決めていなければ再起動してよいか聞く。
- `UPDATE` — 列は `知らせの行 pane_id Herdr名 端末タイトル セッションID cwd`。`OVER` と同じに扱う。依頼文の理由は「Claude Code の更新を反映するため」とする。
- 対象が自分自身なら「Yorozuya 自身を再起動する」に進む。
- 知らせを扱う前に、ペインのセッションIDを引き直す。知らせのIDと違えば再起動は済んでいるので、捨てる（同じセッションに `OVER` と `UPDATE` が両方来たときなど）。IDの列が `-`（取れなかった）なら、pane_id と端末タイトルで照合する。
- `OVER` と `UPDATE` は、1つの見張りのプロセスからは同じセッションに1回しか出ない。張り直すと、閾値以上のままのセッションや知らせが出たままのセッションにもう一度出る。再起動を依頼して資料のパスを待っているセッションなら捨てる。対象が「止められない」と返したら「詰まったとき」のとおりにし、改めて依頼するのは対象からの返信かユーザーの指示を受けてから。
- `WARN` — 使用率を3回続けて読めないペインがある、または Herdr の一覧が取れない。ユーザーに伝える。`blocked` のペイン（承認や選択式の問いの待ち）はダイアログがステータスラインを隠すので、読めなくても数えない。ステータスラインの形が変わったなら `--pattern` を作り直して走らせ直す。入力欄の見えない画面（トランスクリプト表示など）も読めない扱いになるので、ペインを見て確かめる。
- 再起動の最中に別の知らせが来たら、今の再起動を終えてから順に扱う。

## Yorozuya 自身を再起動する

`scripts/restart-self.mjs <資料の絶対パス>` を使う。**手順を持つのは生き残る側**（新セッション）。
死ぬ側が `/exit` を送るとスクリプト自身も消えるため、依存を逆転させてある。
旧ペインを閉じるのも報告するのも新セッション。

呼ぶ前に**資料を自分で書く**。handoff スキルは model から呼べないため。
そのスキルの指示（一時ディレクトリに絶対パスで保存・推奨スキルを挙げる・既存の成果物は参照で済ませる・
秘密情報は伏せる）に従う。加えて、引き継ぎ先は**検証役でもある**ので「何を確かめてほしいか」を書く。
旧セッションは死んでいて自分では確かめられない。
手順2の依頼文と同じく、冒頭に再起動に取りかかる前の状態（作業の途中・ユーザーの答えや操作の待ち・指示待ち）も書く。答えや操作の待ちなら、問いや頼んだ操作の文面と選択肢をそのまま書く。
全体の流れの置き場と、今の作業がその中のどこにあたるかも、手順2の依頼文と同じく書く（置き場のずれの扱いも手順2と同じ）。

**呼んだら黙って止まる。** 成功（終了コード 0）なら、それ以上何も出力しない。
報告も要約も別れの言葉も要らない。
旧ペインは資料を読み終えた新セッションに閉じられるので、書いても誰にも読まれないまま消える。
ユーザーへの報告は新セッションの仕事。
**終了コード 1（SKIP でも FAIL でも）のときは報告する。** そのときは旧セッションが生き残っていて、伝えられるのはこちらしかいない。

**呼ぶ前に、自分のバックグラウンドの処理が残っていないことを確かめる。**
ペインごと閉じて強制終了するので、走っているものは巻き添えになる。
他セッションの再起動の最中に自分を殺すと、対象が `/exit` と起動の間で取り残される。
コンテキストの見張りを走らせているなら TaskStop で止め、走らせ直すコマンド（パターンと閾値を含む）を資料に書く。
再起動を依頼して資料のパスを待っているセッションと、「止められない」と返してきたセッションも書く。張り直した見張りは同じ知らせをもう一度出すので、新セッションが捨てるかを決める材料になる。

## 知っておくこと

- 再起動した新セッションの進め方は、`scripts/lib/prompts.mjs` の `HOW_TO_PROCEED` にある（2つのスクリプトが同じ文を送る）。資料に書かれた状態から続け、再起動を知らせる問いは出さない。再起動したことは、自己再起動では新セッションが、ほかは呼び出し元が報告する。
  新セッションがダイアログ（AskUserQuestion）で問いを出し直すと、答えるまでそのペインは `blocked` で、見張りからは使用率を読めず、`herdr agent prompt` も届かない。
- 自己再起動には、手順6にあたる確かめが無い。新しいペインの入力欄に依頼が残っていたら、ユーザーが Enter を押す。
- 実行中にこのセッションが終わると、スクリプトも止まり、対象が終了したまま残ることがある。
  旧セッションID は最初のログに出ているので `claude --resume <ID>` で戻せる。
- 対象のコンテキスト使用量を、外からトークンで数えない。モデルごとに違う上限をこちらが決め打ちすることになる。
  見張りが読むのは、ステータスラインが上限を踏まえて出した使用率。
- 見張りを走らせていなければ、**他セッションの増加に自分で気づく契機は無い**。ユーザーの指示か対象の申告から始まる。
