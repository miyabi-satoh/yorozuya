# desk-inspection

リポジトリ全体を読むだけで欠陥を洗い出す「机上検査」を、領域ごとのサブエージェントで流し、確かめ直した指摘だけを重さ順のレポートにする。

## 読む前に

- **この skill の形では、まだ最後まで通していない。** 手順とレポートの組みは、同じやり方を手で2回流したときのものを写している
- **Claude Code の Agent ツールと Artifact ツールを前提に書いている。** サブエージェントのモデルは Agent ツールの `model` で選ぶ。ほかのエージェントでは、サブエージェントの起動とレポートの出し方を読み替える（レポートは HTML ファイルでも出せる）
- **使用量の枠を大きく使う。** 領域の数だけサブエージェントがリポジトリを読む。並べる数は、5時間枠の使用量を測りながら決める（weekly-pace の `claude-usage.mjs` を使う。無ければ2つずつ順に流す）
- **手で呼ぶときだけ動く**（`disable-model-invocation: true`）。Codex でも暗黙には呼ばれない（`agents/openai.yaml`）
- `scripts/check-locations.mjs` は Node と git が要る。Node 26 で確かめた

## できること

- リポジトリのコード・文書・マニュアル・配り方の設定を領域に分け、領域ごとに、データを失う・止まったまま戻れない・決めごとや文書との食い違い・OS ごとの落とし穴などを探させる
- 返った指摘を1件ずつコードと依存の手元の版のソースで辿り直し、確かめられないものと理論上だけのものを落とす。OS の実際の動きで決まるものは「実機で確かめたいこと」に回す
- 重さ順の節・指摘ごとの 起きること／理由／確かめ方／場所／直す方向・OS と確かめの度合いのタグ・対応の状況のタグを持つレポートを出す。直した後に、対応の状況を書き足して出し直せる
- レポートに書いた `path:line` が、検査したリポジトリのファイルの長さに収まるかを機械で確かめる
- サブエージェントのモデルと最初に並べる数は、`SKILL.md` の「設定」の1か所で変えられる

## 使い方

検査したいリポジトリのセッションで `/desk-inspection` と打つ。検査の時期（「公開の前に」など）は指示ファイルから、大事な OS はリポジトリが対応している OS から決めるので、添えなくてよい。資料と違う時期や OS で見たいときだけ添える。

## 中身

| | |
| --- | --- |
| `SKILL.md` | 手順と設定 |
| `references/area-prompt.md` | 領域ごとのサブエージェントへの依頼文のひな形 |

| `scripts/check-locations.mjs` | レポートの `path:line` がリポジトリの中に収まるかを確かめる |
